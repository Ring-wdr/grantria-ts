# UI/UX 현대화 검토: 편의 기능과 추가 콘텐츠

2011년 원본의 규칙(20 FPS 틱, 전투·수치·드롭·스토리 진행)을 그대로 두고, 2026년 기준으로 무엇을 더할 수 있는지 정리한다. 코드 위치는 2026-10-13 `main` 기준이다.

## 0. 판단 기준: "본질을 건드리지 않는다"

다음 조건을 모두 지키는 것만 편의 기능으로 분류한다.

1. **규칙 불변**: `src/core/rules`, `src/core/combat`의 공식·확률·쿨다운·드롭은 바꾸지 않는다. 고칠 곳은 대부분 `src/web`(표시·입력·흐름)이다.
2. **틱 불변**: 이벤트 시계, 보스 패턴, 몬스터 AI가 도는 20 FPS 틱을 빨리 돌리거나 건너뛰지 않는다.
3. **원본 동작으로 되돌릴 수 있음**: 체감이 크게 달라지는 기능은 옵션으로 두고, 기본값은 원본 동작이거나 원본과 결과가 같은 쪽으로 둔다.
4. **세이브 호환**: 슬롯 세이브(`src/core/save/save.ts`) 형식은 바꾸지 않는다. 새 상태는 `options`, `keys`처럼 별도 키에 둔다. 원본 `save.dat` 내보내기도 계속 되어야 한다.

자동 전투, 자동 물약, 전투 배속, 지도에서 바로 순간이동처럼 난이도나 탐험 흐름을 바꾸는 기능은 **경계선** 항목으로 따로 표시했다(§6).

## 2. 대사·이벤트 편의 (가장 효과가 크다)

대사가 떠 있는 동안 이벤트 시계는 멈춰 있다(`wait === 1`, `events.ts:201`). 그래서 **대사를 빨리 넘기거나 자동으로 넘겨도 이벤트 타이밍은 바뀌지 않는다.** 아래 기능은 모두 원본 연출을 그대로 둔다.

| # | 기능 | 내용 | 손댈 곳 | 우선 |
|---|---|---|---|---|
| D1 | **대사 로그(백로그)** | 이벤트 대사, NPC 대화, 자막(CAPTION)을 `{화자, 얼굴, 텍스트 id, 본문}`으로 쌓는다(세션당 200개 링 버퍼). 대사 중 로그 키(패드: 오른쪽 스틱 위 또는 R2, 터치: 대사창 위 아이콘)로 연다. 이벤트 진행은 멈춘다 | 기록: `events.ts:318`(TALK), `:371/376`(자막), `fieldScene.ts:1108`(NPC). `Dialogue`에 `textId`를 보관한다. 뷰: 새 `web/game/backlog.ts` | P0 |
| D2 | **자동 진행** | 페이지가 다 나온 뒤 `글자 수 × k + 기본 대기` 틱이 지나면 확인과 같은 경로로 넘긴다. 켬/끔은 대사 중 토글(AUTO 버튼)과 옵션 두 곳에 둔다 | `events.ts:196-197`, `fieldScene.ts:1866`의 `advance()` 호출부 | P0 |
| D3 | **텍스트 속도** | 느림(원본: 1자/틱)·보통(2자)·빠름(4자)·즉시. 타자기만 바꾼다 | `Dialogue.tick()` | P0 |
| D4 | **누르고 있으면 빨리 넘기기** | 확인 키나 터치를 누르고 있으면 페이지를 바로 채우고 몇 틱마다 넘긴다. **VM을 한 프레임에 여러 번 돌리지는 않는다**: 0x27 대기는 실제 시간(`performance.now`)이고, 보스와 문 장벽이 이벤트 시계를 읽기 때문이다(`events.ts:225`, `fieldScene.ts:1021-1026`, `:1856`) | `events.update`, `fieldScene` 대화 처리 | P1 |
| D5 | **읽은 대사만 빨리 넘기기** | 본 텍스트 id를 별도 키(`grantria.read`, 계정 공용)에 비트셋으로 저장한다. D4는 읽은 대사에서만 동작하는 것이 기본이고, 옵션으로 "전부"를 고를 수 있다. 읽은 대사는 로그와 대사창에서 색으로 구분한다 | `Story`나 슬롯 세이브는 건드리지 않는다 | P1 |
| D6 | **SKIP 개선** | ① 퀘스트 명령 0x13/0x14는 상태 변경(`quests.accept/complete`)을 그대로 하고 팝업만 결과 요약으로 모아 마지막에 한 번 보여 준다. 그러면 한 번 눌러 이벤트 끝까지 갈 수 있다. ② 건너뛸 수 없는 구간에서도 버튼을 흐리게 남겨 깜빡이지 않게 하고, 누르면 "스킵 예약" 후 가능해지는 순간 실행한다. ③ 원본처럼 처음 보는 이벤트도 스킵할 수 있게 두되 확인 팝업을 띄운다 | `fastForward()` `events.ts:426-451` | P1 |
| D7 | 페이지 끝 표시 | 페이지가 다 나오면 오른쪽 아래에 ▼가 깜빡인다(원본에는 없다) | `Dialogue.draw()` | P0 |
| D8 | 잘못 누름 방지 | "화면 어디나 탭 = 확인"을 대사창·확인 버튼 영역으로 좁히는 옵션. 페이지가 바뀐 직후 150ms는 입력을 무시한다 | `events.ts:502`, `fieldScene.ts:2141` | P1 |
| D9 | NPC 대화 얼굴 | NPC 대화도 이벤트처럼 `faceOf()`로 얼굴을 찾아 보여 준다(얼굴이 있는 인물만) | `fieldScene.ts:1108` | P2 |

**구현 메모**
- D1~D3, D7은 `src/web`만 바꾼다. 상태는 `options`(텍스트 속도, 자동 진행)와 새 키 하나(`grantria.read`)뿐이다.
- 반복 힌트 이벤트(`REPEATABLE`, `events.ts:22`)는 매번 처음부터 다시 나온다. D5가 있으면 이 이벤트들이 가장 먼저 편해진다.

## 9. 구현할 때 지킬 것

- 새 설정은 `Options`에 넣되 `OPTION_KEYS`(원본 option.dat 5줄)와 분리한다. 원본 option.dat 내보내기는 지금처럼 5줄만 쓴다(`fullscreen` 처리와 같다).
- 새 상태(읽음 기록, 잠금, 추적 퀘스트, 도감·기록)는 슬롯 세이브가 아니라 별도 저장소 키에 둔다. 슬롯마다 따로여야 하면 `grantria.<기능>.<슬롯>`으로 두고 데이터 관리 화면의 JSON 백업에 같이 넣는다.
- 원본 연출을 바꾸는 것(SKIP 동작, 탭 영역)은 옵션의 기본값을 원본으로 둔다.
- 대사·이벤트를 빠르게 하는 기능은 이벤트 시계와 VM 실행 횟수를 바꾸지 않는다(§2 D4). `tests/`에 "자동 진행·빨리 넘기기로 이벤트를 끝까지 돌려도 플래그·퀘스트 결과가 일반 진행과 같다"는 테스트를 둔다.
- 새 UI는 키보드·패드·터치 셋 다 조작할 수 있어야 한다(키 설정에 새 동작 추가, 터치 버튼, 패드 버튼 표시).

확인 방법: `npm run typecheck`, `npm test`(규칙: 옵션, 읽은 대사, 비교, 일괄 판매, 출석, 기록, 추가 도전과제), `vite build`. 그 뒤 원본 APK에서 만든 에셋으로 게임을 띄워 대사 로그·자동 진행, HUD 정보, 출석, 편의 설정, 기록실과 회상(세이브가 바뀌지 않는지)을 확인했고, 거기서 나온 문제를 고쳤습니다.

- S2 슬롯 정보 패널은 뺐습니다. 원본 슬롯 카드가 이미 플레이 시간·지역·하드 표시를 보여 주고, 패널은 돌아가기 버튼에 가렸습니다. 대신 카드 왼쪽 위에 회차 숫자만 작게 붙입니다.
- 대사 로그·자동 진행 접근성: 원본의 쿠폰상점 HUD 버튼을 없애고(쿠폰상점은 커뮤니티 메뉴에 남음) 그 자리에 대사 로그 버튼을, 필드 D패드 →에 대사 로그를 두었습니다. 대사창 LOG/AUTO 버튼과 로그 창 아래에 장치별 키 표시를 붙이고, K로 필드 어디서나 자동 진행을 켜고 끕니다.
- 회상은 타이틀 화면으로 옮겼습니다. 회상 버튼을 누르면 이야기 전체가 순서도로 나옵니다(`core/data/storyChart.ts`): 세 캐릭터의 오프닝 이야기(러스티 1~9, 엘 10~19, 알피 20~29)가 나란히 내려와 이벤트 30(초원 - 고대유적)에서 합쳐지고, 그 뒤는 직업과 상관없이 하나인 길을 장(章)별로 잇습니다. 순서는 이벤트 헤더의 트리거 사슬(선행 이벤트, 보스 처치)을 따랐고, 재생할 수 있는 이벤트가 모두 한 번씩 들어 있는지는 테스트(`tests/storychart.test.ts`)가 확인합니다. 본 이벤트와 그 캐릭터의 길(자기 오프닝 → 공통 길)에서 그보다 앞선 이벤트를 재생할 수 있고(이벤트 9를 봤으면 1~8도: 기록이 생기기 전 버전에서 지나간 이야기를 위해, `seenAlongRoute`), 공통 이벤트는 고른 시점(캐릭터)이 봤으면 그 캐릭터로, 아니면 본 캐릭터로 재생합니다. 「이어서 보기」(C / L2, 설정에 저장)를 켜 두면 장면이 끝나거나 SKIP했을 때 같은 캐릭터의 길에서 다음으로 볼 수 있는 장면이 바로 이어지고, Esc를 누르면 멈추고 순서도로 돌아옵니다. 회상 장면에서도 LOG·AUTO를 쓰며, 로그는 그 장면의 대사만 따로 담습니다. 본 이벤트는 이벤트가 끝날 때 직업별로 계정 공용 기록(`records.seen`)에 남기고, 재생은 새 게임 상태에 그 목록만 반영해 만듭니다. 그래서 회상 목록이 슬롯 진행에 묶이지 않습니다. 이전 슬롯은 처음 열 때 한 번 가져옵니다(끝 훅이 재생 없이 표시한 이벤트는 읽은 대사가 있을 때만, 다른 직업의 오프닝은 제외). 오프닝 이벤트(헤더 맵 -1)는 직업의 첫 맵에서 재생합니다. 회상 횟수는 SKIP·Esc 없이 끝까지 본 것만 셉니다.
- 기록실은 게임 메뉴 → 환경설정 탭의 몬스터도감 줄을 바꾼 것입니다: 몬스터 도감·아이템 도감·보스 기록(보스 러시)·도전과제·출석·심연 목록에서 고릅니다. 필드의 회상 버튼은 없앴습니다.
